# 5.2.10 Complete Web Application Integration

## 1. Overview and Overall Architecture

The complete trained deep learning framework—integrating **YOLOv8**, **Swin-UNet**, **DenseNet-121 Multi-Specialist Classifiers**, and **Grad-CAM Explainable AI (XAI)**—is integrated into an end-to-end, full-stack clinical web application.

```
                    USER
                      ↓
                 FRONTEND (React + MUI)
                      ↓
                 MRI Upload (.png, .jpg, .h5)
                      ↓
                 BACKEND (FastAPI + Supabase)
                      ↓
              AI Processing Engine (PyTorch)
                      ↓
              ┌───────┴───────┐
              ↓               ↓
           YOLOv8        Preprocess & Slice Selection
              ↓
         Candidate ROI
              ↓
      Background Blurring + Swin-UNet
              ↓
         Tumor Mask & Contours
              ↓
      Context-Aware ROI Patch (+15% Margin)
              ↓
     DenseNet-121 Multi-Specialist Classifier
              ↓
    Clinical Open-Set Recognition Calibration
              ↓
         Grad-CAM Explainable AI (XAI)
              ↓
     Final Results & Multi-Panel Image Synthesis
              ↓
           Backend (Database Persistence)
              ↓
          Frontend (5-Panel Viewer & PDF Report)
              ↓
                    USER
```

## 2. Frontend Implementation

* **Primary Files:** `frontend/src/pages/PredictPage.tsx`, `frontend/src/apiService.ts`, `frontend/src/utils/pdfGenerator.ts`
* **Technologies:** React 18, TypeScript, Material-UI (MUI v5), Vite, HTML5 Canvas API, jsPDF, html2canvas.

### Key Components and Functionality:
1. **Interactive Dropzone & Client-Side Validation:**
   - Supports drag-and-drop file upload and native file browser selection for standard formats (`.jpg`, `.jpeg`, `.png`) and 3D MRI slice files (`.h5`).
   - Validates file size (max 10MB limit) and MIME types before sending requests to prevent unnecessary server load.
2. **Dynamic Multi-Stage Progress Tracking:**
   - Provides real-time feedback with a multi-phase animated progress bar that dynamically updates through each deep learning stage:
     - `0% - 25%`: *Preprocessing MRI scan & normalizing slices*
     - `25% - 55%`: *Extracting Swin-UNet deep transformer features*
     - `55% - 80%`: *Localizing lesions & calculating YOLOv8 boundaries*
     - `80% - 100%`: *Synthesizing Explainable AI (Grad-CAM) insights*
3. **Persistent Module-Level State Caching:**
   - Implements persistent module caching (`persistedFile`, `persistedResult`, `persistedImagePreview`) so diagnostic visualizations remain intact across route switches and page transitions.
4. **Dual Authentication Support:**
   - **Guest Mode:** Instant scan analysis without requiring user login (scans are transient).
   - **Authenticated Mode (Supabase Auth):** Automatically sends Bearer JWT tokens with API requests to store diagnosis records in the cloud for historical auditing.

## 3. Backend Implementation

* **Primary Files:** `backend/app/main.py`, `backend/app/inference/classifier.py`, `backend/app/records/records_handler.py`, `backend/app/validation/file_validator.py`
* **Technologies:** FastAPI (Python 3.10+ async framework), Uvicorn, Pydantic, HTTPX, Pillow, OpenCV, Supabase Python SDK.

### Key Components and Functionality:
1. **In-Memory IP Rate Limiting:**
   - Uses a sliding window algorithm (`MAX_PREDICTIONS_PER_WINDOW = 10` requests/min per client IP) to protect backend and AI inference resources from abuse.
2. **Server-Side File Verification:**
   - Verifies file signatures, byte integrity, and image headers using `file_validator.py` to prevent corrupt files or malformed inputs from reaching the AI pipeline.
3. **Decoupled Asynchronous Microservice Communication:**
   - The FastAPI backend accepts uploads via `POST /api/predict`, forwards the payload asynchronously via `httpx.Client` to the PyTorch inference microservice (`http://localhost:8080/api/predict`), and handles response deserialization.
4. **Self-Healing Fallback Diagnostic Engine:**
   - In `classifier.py`, if the remote deep learning worker is temporarily unreachable during restarts, the backend seamlessly triggers a built-in diagnostic pipeline to maintain service availability.
5. **Database and Storage Integration:**
   - For authenticated users, `records_handler.py` uploads MRI scans to Supabase Storage and records prediction metrics (label, confidence score, segmented pixel count, model version, timestamp) into PostgreSQL.

## 4. Model Loading & Initialization

* **Primary Files:** `NeuroAI/Neuro_AI_System.py`, `NeuroAI/extracted_pipeline/pipeline_yolo_seg.py`
* **Technologies:** PyTorch, Ultralytics YOLOv8, Torchvision DenseNet-121, Hierarchical Swin-UNet (SimMIM Pretrained).

When the AI system initializes via `load_local_models()`, all weights and network architectures are loaded into memory:

1. **Device Selection:** Automatically detects CUDA GPU availability and routes tensors to GPU; falls back to CPU if necessary.
2. **YOLOv8 Detector:** Loads fine-tuned bounding box weights (`yolo_best.pt`) to locate candidate tumor ROIs.
3. **Swin-UNet Segmentation Model:** Loads the hierarchical shifted-window Swin-UNet backbone with configuration `swin_base_patch4_window7_224_finetune.yaml` and trained weights `output_finetune/best_model.pth`. Uses robust prefix-matching to resolve state dictionary keys (`module.`, `swin_unet.`, `model.`).
4. **DenseNet-121 Multi-Specialist Classifier:** Loads 4 specialized binary classification networks (`densenet121_glioma.pth`, `densenet121_meningioma.pth`, `densenet121_pituitary.pth`, `densenet121_notumor.pth`), each configured with a customized classifier head (`Linear(1024, 512) -> ReLU -> Dropout(0.3) -> Linear(512, 2)`).

## 5. End-to-End Inference Sequence

The complete diagnostic execution runs across seven sequential stages:

```
[Input MRI Scan (.png / .jpg / .h5)]
               │
               ▼
┌──────────────────────────────────────────────┐
│ Stage 1: Input Preprocessing & Normalization │
│ - Selects highest variance slice for .h5     │
│ - Scales pixel intensities to [0, 255]       │
└──────────────────────┬───────────────────────┘
                       │
                       ▼
┌──────────────────────────────────────────────┐
│ Stage 2: YOLOv8 Region Detection             │
│ - Predicts candidate bounding box [x1,y1,x2,y2]
└──────────────────────┬───────────────────────┘
                       │
                       ▼
┌──────────────────────────────────────────────┐
│ Stage 3: Background-Blurred Swin-UNet        │
│ - Blurs non-lesion background                │
│ - Predicts pixel-accurate tumor mask & edges │
└──────────────────────┬───────────────────────┘
                       │
                       ▼
┌──────────────────────────────────────────────┐
│ Stage 4: Context-Aware ROI Patch Extraction  │
│ - Crops unblurred patch with +15% margin     │
│ - Standardizes to 224x224 and normalizes     │
└──────────────────────┬───────────────────────┘
                       │
                       ▼
┌──────────────────────────────────────────────┐
│ Stage 5: DenseNet-121 Multi-Specialist Eval  │
│ - Evaluates patch across 4 specialist heads  │
│ - Computes softmax probabilities             │
└──────────────────────┬───────────────────────┘
                       │
                       ▼
┌──────────────────────────────────────────────┐
│ Stage 6: Clinical Open-Set Calibration       │
│ - Confirmed Tumor: Best score >= 65%         │
│ - Normal Scan: NOTUMOR score >= 50%          │
│ - Atypical: Score < 65% -> UNRECOGNIZED      │
└──────────────────────┬───────────────────────┘
                       │
                       ▼
┌──────────────────────────────────────────────┐
│ Stage 7: Explainable AI (Grad-CAM) Synthesis │
│ - Hooks denseblock4 feature maps & gradients │
│ - Overlays JET heatmap (60% image + 40% CAM) │
└──────────────────────────────────────────────┘
```

## 6. Communication Between Backend and AI Models

* **Protocol:** HTTP/REST with JSON data interchange.
* **Payload Encoding:** Images are encoded as Base64 data URIs (`data:image/png;base64,...`) to allow transport without disk write bottlenecks.
* **Response Structure:**
```json
{
  "status": "success",
  "filename": "patient_scan_flair.png",
  "pred_class": "GLIOMA",
  "conf_percent": 97.45,
  "segmented_pixels": 4280,
  "explanation_text": "=================================================================\n 🩺 EXPLAINABLE AI (XAI) ASSISTANCE REPORT\n=================================================================\n...",
  "images": {
    "bbox": "data:image/png;base64,iVBORw0KGgo...",
    "seg": "data:image/png;base64,iVBORw0KGgo...",
    "combined": "data:image/png;base64,iVBORw0KGgo...",
    "five_panel": "data:image/png;base64,iVBORw0KGgo..."
  }
}
```

## 7. Result Generation & Visual Artifacts

The system produces standardized diagnostic artifacts:
1. **YOLOv8 Bounding Box (`complete_test_bbox_output.png`):** Localizes lesion coordinates in the MRI frame.
2. **Swin-UNet Segmentation Mask (`complete_test_seg_output.png`):** Delineates the tumor perimeter with a vivid red contour boundary.
3. **Combined Overlay (`complete_test_combined_output.png`):** Merges both bounding box and segmentation mask onto the original scan.
4. **5-Panel Diagnostic Overview (`complete_diagnosis_5panel_output.png`):** Presents a comprehensive 5-stage visual verification strip:
   - Panel 1: Original Scan
   - Panel 2: YOLO Detection
   - Panel 3: Swin-UNet Segmentation
   - Panel 4: Combined View
   - Panel 5: Grad-CAM Explainable AI Heatmap

## 8. Visualization in the User Interface (UI)

The frontend presents diagnostic findings through an interactive clinical dashboard:

1. **Color-Coded Diagnostic Themes:**
   - **Glioma:** Vivid Heat Red (`#FF5A46`)
   - **Meningioma:** Amber Gold (`#FFB238`)
   - **Pituitary:** Signal Cyan (`#5CC8FF`)
   - **Unrecognized / Atypical:** Warning Orange (`#F59E0B`)
   - **No Tumor (Healthy):** Clear Mint Green (`#4ADE9C`)
2. **Radial Confidence Gauge:** An animated circular SVG meter displaying the exact model confidence percentage.
3. **Tabbed Visual Overlay Viewer:** Allows clinicians to toggle between the **5-Panel Overview**, **Combined View**, **Swin-UNet Mask**, and **YOLO Bounding Box**, with support for a full-screen **Lightbox Modal** with high-resolution zoom.
4. **Segmented Area Metric:** Displays the quantified abnormal tissue surface area (e.g., *4,280 pixels*).
5. **Dual-Audience XAI Reports:**
   - **👨‍⚕️ Radiologist / Clinician View:** Outlines Grad-CAM activation zones, margin irregularities, peritumoral edema, and recommended radiological protocols (e.g., contrast T1w, perfusion MRI, MR spectroscopy).
   - **👤 Patient & Family View:** Explains the findings in clear language with guidance on discussing the scan with a doctor.
6. **Automated Clinical PDF Report Generator:** Enables one-click downloading of PDF medical summaries containing patient metadata, classification confidence, tumor area, embedded MRI overlays, and clinical remarks.
